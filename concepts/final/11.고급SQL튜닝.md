고급 SQL 튜닝
  - 소트 튜닝
    - 메모리 소트 / 디스크 소트
    - PGA 에서 할당(소트영역)
    - 메모리 공간 부족 -> Oracle -> temp table Space, SQL Server -> tempdb
    - 메모리 소트 -> 소트영역내 완료 -> Internal, Optimal Sort
    - 디스크 소트 -> 디스크사용 소트 -> External Sort
      - One Pass Sort -> 디스크로 1번
      - MultiPass Sort -> 디스크로 1번 이상
     
    - 소트 발생 오퍼레이션
      - Sort Aggregate -> 전체 로우 대상 집계
      - Sort Order by : 정렬 결과
      - Sort Group by : Sorting을 통한 그룹별 집계
      - Sort Unique : 결과 집합 중복 레코드 제거
      - Sort Join : 소트 머지 조인 수행시
      - Winodw Sort 윈도우 함수 수행
     
    - 소트 튜닝 -> CPU 집약적 -> Sort 많을 수록 -> 성능이 떨어짐
   
    - 튜닝 방안
      - 소트 사용 없이 SQL 작성
        - Union -> Union all로 변경
        - Distinct -> Exists 서브쿼리로 대체
          ```
          select distinct ~ from ~

          select ~ from ~
          where
          and exists (select 'x' from ~ )
          ```
      - 데이터 모델에서 검토
        - group by, union, distinct 연산자 많이 사용-> 데이터 모델 정규화 제대로 안되어있는 경우 의미
      - 인덱스 사용 소트 대체
        - Sort Order by 대체 -> 인덱스 등치조건(선두컬럼) + order by 인덱스 컬럼 사용
        - Sort Group by 대체 -> group by + 인덱스 선두 컬럼 / Sort Group by no sort
        - 인덱스 활용 Min, Max
          - First Row Stopkey 알고리즘
          - 인덱스 선투컬럼 -> 조건 + max(인덱스컬럼) or min(인덱스컬럼)
          - 실행계획 -> First Row 발생
      - 소트영역을 줄이도록 -> SQL 작성
        - 소트 영역 늘리기 보다는 적게 사용
        - 소트 완료 후 데이터 가공
          ```
          select ~ from (select ~ from ~ roder by ~ )
          ```
      - 소트영역 크기 조정
      - 불필요한 count 연산 제거
        - rownum >= 1 있는지로 판단

Top N 쿼리 이용
```
SQL Server -> select Top 10 ~
DB2 -> select ~ from ~ fetch 10 rows only
Oracle -> select * from ( ~ order by 거래일시 ) -> 인덱스로 Sort 생략해야됨
          where rownum <= 10
```

  - Top N Sort 알고리즘 작동 되는 케이스
```
select ~ from
    (select ~
          , max(변경순번) over(partition by 고객ID) ~
          , ~
      from 고객변경이력)
where 변경순번 = 마지막 변경순번

select ~
from (select ~
          ,rank() over(partition by 고객ID order by 변경순번) rnum
          , ~
where rnum = 1
```

  - Top N 쿼리 이용 효과적인 이력 조회
```
1. /*+ INDEX_DESC(X ~) */ + ROWNUM <= 1
  - 인덱스 구성이 완별해야함

  select ~
    , (select /*+ INDEX_DESC(X 상태변경이력_PK) */
            , 변경일자 || LPAD(변경순서, 4) || 상태코드
        from ~
        where 장비번호 = P.장비번호
        and rownum <= 1)
  from 장비 p
  where 장비구분코드 = 'A001'

2. 12버젼 부터 내부쿼리 조인(메인 + 이력) -> order by -> rownum <= 1

select ~
from (
    select ~
        ,(select 변경일자||LPAD(변경순번, 4) || 상태코드
          from (select 변경일자, 변경순번, 상태코드
                from 이력
                where 장비번호 = P.장비번호
                order by 변경일자 desc, 변경순번 desc)
          where rownum <= 1 ) 최종이력
    from 장비 P
    where 장비구분코드 = 'A001'
)

select ~
  ,(select ~
    from (select ~
          from 이력
          order by ~ desc, ~ desc
    where 장비번호 = P.장비번호
    and rownum <= 1) 최종이력
from 장비 P
where 장비구분코드 = 'A001'
```
