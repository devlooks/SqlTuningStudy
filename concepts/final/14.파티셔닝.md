파티셔닝
  - 관리적 측면 : 파티션 단위 백업, 추가,삭제, 변경
  - 성능적 측면 : 파티션 단위 조회 및 DML 수행, 경합 및 부하 분산
  - 파티션 유형
    - Range : 파티션 키 값 범위로, 일반적 형태, 주로 날짜 컬럼 기준
    - Hash :
      - 파티션 키 + 해시함수 -> 반환 값으로 파티션 매칭
      - 모든 파티션에 데이터 고르게 분포 DBMS 관리
      - 데이터 분포가 고른 컬럼 선정 -> 표과적
      - 병렬 처리시 극대화
      - DML 경합 분산 효과적
     
    - LIST
      - 불연속 값 목록 -> 파티션 지정
      - 사용자 기준에 따라 데이터 분할 저장
     
    - Composite : 파티셔닝
      - Range 나 list 파티션 내, 서브파티션 구성
      - Range나 list 파티션이 갖는 이점 + 각 서브 파티션 구성의 이점

```
  create table 주문(주문번호 number, 주문일자 varchar2(8), 고객id varchar2(5), ~ )
  partition by range(주문일자)
  (partition p2009_q1 values less than ('20090401'),
   partition p2009_q2 values less than ('20090501'),
      ....
  );

  create table 주문 ( ~ )
  partition by range (주문일자)
  subpartition by hash(고객Id) subpartition 8 ( ~ )
```

파티션 Pruning
  - 정적 -> 상수조건으로 조회하는 경우
    - pstart : 숫자
    - pstop : 숫자
  - 동적 -> 바인드 변수로 조회
    - pstart : key
    - pstop : key
  - 파티션 가공해서 사용시, Pruning 안됨

  - 인덱스 파티셔닝
    - local 파티션 인덱스 -> 테이블 파티션과 1:1
    - Global 파티션 인덱스 -> 테이블 파티션과 독립적 구성
    - Prefixed 파티션 인덱스 -> 파티션 키 컬럼 -> 선투컬럼
    - Non Prefixed 파티션 인덱스 -> 파티션 키 컬럼 -> 선두컬럼X

  - 인덱스 파티셔닝 가이드
    - local
      - 관리적 측면에 좋음
    - global
      - 테이블 Drop, Exchange, Split 등... 하게 되면, 인덱스 (Global) Unusable 처리 -> Rebuild 처리 해야함

    - 비파티션
      - OLTP 환경, NL 조인 사용, 부분 범위처리(소트연산 생략 가능)
      - 테이블 파티션 이동, 삭제 등 작업시 인덱스 unusable -> 적용됨 주의

    - Global Prefixed
      - 인덱스 경합 분산위 효과적, local 비효율시 대안
      - 테이블 파티션 이동, 삭제 등... 인덱스 unusable 상태 적용 주의

    - Local Prefixed
      - 테이블 파티션 추가, 삭제 등 작업 빈번
      - 이력성 테이블 DB 환경, 파티션 키 등치 조건

    - 파티셔닝 칼럼 컴색 조건이 없거나, 인덱스 선두 컬럼에 조건절이 누락시 정상 사용 불가능
    - 파티션 키 칼럼 -> 범위 조건으로 사용 -> 불리
   
    - Local Non Prefixed
      - 테이블 파티션 추가/삭제 등 작업 빈번
      - 이력성 데이터 주로 관리 DB 환경 효과적
      - 파티션 키 컬럼 조건절에 사용
      - 검색조건 x -> 파티션 전체 액세스 비효율 발생
      - 파티션 키 범위 조건 자주 사용
        - Local Non Prefixed 유리
        - 좁은 범위
