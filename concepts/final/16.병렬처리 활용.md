  - Query Coordinator와 병렬 서버 프로세스
    - 병렬 SQL 시작 -> 사용자 지정 병렬도에 따라 병렬서버 집합 할당
      - 우선 서버풀로 부터 서버프로세스 확보 -> 그 이후 부족분 생성  
        (parallel Execution Server Pool)
      - 각 병렬 서버에 작업 할당 -> 제대로 진행 되는지 관리 감독
      - 병렬 처리 되도록 사용자가 지시X, 테이블 QC 직접 처리
      - QC
        - 각 서버 산출물 통합 작업 수행
        - 최종 결과 사용자에게 전송, DML 일시 갱신건수 집계 전송
       
      - Intra-Operation Parallelism
        - 서로 배타적인 범위 독립적 동시 처리
          
      - Inter-Operation Parallelism
        - 정렬된 결과를 QC에 전송 작업 병렬도 동시에 진행
        - 항상 프로세스간 통신
       
      - 테이블 큐
        - Intra-Operation Parallelism
          - 여러 프로세스가 처리 범위를 달리하면서 병렬처리
          - 프로세스간 통신 발생X
        - Inter-Operation Parallelism
          - 프로세스간 통신 발생
          - P -> P
          - 병렬수 X2 -> 서버 갯수

병렬 실행 계획에서 생산자 / 소비자 식별 방법

  - 생산자 SEND
  - 소비자 RECEIVE

```
  select statement
    PX COORDINATOR
      PX SEND QC                  -> Q2, 02
        SORT ORDER BY
          PX RECEIVE              -> Q1, 01 
            PX SEND
              HASH HOIN
                  ....
                    PX RECEIVE    -> QC
                      PX SEND BROADCASE : TQ10000   -> S->P/BROADCASE

    1. QC가 DEPT 테이블 읽어 (Q1, 01에 전송)
    2. Q1, 01 -> EMP 테이블 병렬도 읽으면서, DEPT 테이블과 조인 -> Q1, 02로 전송
    3. 전송 레코드 정렬, QC 전송
```

  - IN-OUT Operation
    - serial : 시리얼 하게 실행 (직렬)
   
    - 프로세스간 통신 O
    - S->P (P from S) : QC 처리 결과 병렬 프로세스 전달
    - P->S (P To S)   : 병렬서버 프로세스 처리 결과 QC 전달
    - P->P (P To P)   : 두 개의 병렬서버 프로세스 집합 처리, 병렬도의 2배 병렬 프로세스 생성
   
    - 프로세스간 통신 X
    - PWCP            : 현재 스탭 + 부모 스탭 모두 처리
    - PCWC            : 현재 스탭 + 그 자식 스탭 모두 처리

데이터 재분배
  - Range
    - order by, sort group by 병렬로 처리시 사용
    - 두번째 처리 집합 처리 범위 지정
    - 데이터 읽는 첫번쨰 -> 두번째에게 정렬 키값에 따라 분배
   
  - HASH
    - hash group by 병렬처리
    - P->P, S->P 방식 사용가능

  - BROADCAST
    - QC 또는 첫번째 프로세스의 데이터를 두번쨰 서버 집합으로  
      모든 병렬 프로세스로 전송(P->P, S->P)

  - KEY
    - 인덱스 파티셔닝시(특정 컬럼 기준) 사용 분배 방식
   
  - ROUND-ROBIN
    - 반대편 병렬 서버로 무작위 데이터 분배

PQ_DISTRIBUTE 힌트 사용
  - 옵티마이저가 파티션 테이블 적절히 활용 X 동적 재분할 시도 할 경우
  - 기존 파티션 키 무시, 다른 키값으로 동적 재분할
  - 통계정보 부정확 통계 정보 제공 어려운 상황
  - 분배방식 변경 목적

```
  /*+ PQ_DISTRIBUTE(inner, outer, 분배방식) */

  - pq_distribute(inner, none, none)
    - Full-Partition Wise Join 유도
    - 이미 양쪽다 같은 기준으로 Partition 되는 경우

  - pg_distribute(inner, partition, none)
    - Partial-Partition Wise Join
    - Outer 테이블을 inner 테이블 기준(inner 조인키 칼럼)으로 파티셔닝

  - pg_distribute(inner,none,partition)
    - Partial-Partition Wise Join
    - Inner 테이블을 Outer 테이블(Outer조인 키 컬럼) 기준으로 파티셔닝

  - pq_distribute(inner, broadcast, none)
    - Outer 테이블 Boardcast

  - pq_distribute(inner, none, broadcast)
    - inner 테이블 Broadcast
```

  - 병렬 처리시 주의 사항
    - 동시 접속자수 적은 어플리케이션에서만
    - OLTP성 + 수행빈도 작은 쿼리에서
    - 배치 프로그램 전체 수행시간 줄이는데 목표 목적
    - 필요이상의 병렬도는 없으며(최소한의 병렬도 사용)
    - 병렬 DML -> Exclusiv 테이블 Lock, 주간 사용 하면 안됨
