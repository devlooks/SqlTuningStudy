1. 조인 튜닝
   - NL 조인
     - select /*+ ordered use_nl(d) */ -> option(force order)
     - select /*+ leading(e) use_nl(d) */ -> option(force order, loop join)

   - NL 조인의 특징
     - 랜덤 액세스 위조 대량 데이터 비효율
     - 한레코드 씩 순차적 진행
     - 부분 범위 처리시 유리
     - 인덱스 유무에 따라 효율 차이가 큼
     - prefetch I/O, Batch I/O
       - 사용 : nlj_prefetch, nlj_batching
       - 사용X : no_nlj_prefetch, nl_nlj_batching
 
   - NL 조인 수행 과정 분석
```
1) 일반적인 NL 조인 실행 계획
  NL
    TA
      DEPT (1 -> Dept 테이블의 인덱스 컬럼 + 일반 컬럼 조건순
    TA
      EMP (2 -> EMP 테이블의 인덱스 컬럼 + 일반 컬럼 조건순 

2)  prefetch 실행계획
  TA 고객 -> 미리 처리
    NL
      TA
        IRS 사원_X1
      IRS 고객_X1

3) batch I/O
    NL
      NL
        TA 사원
          IRS 사원_idx
        IRS 고객
      TA 고객 -> 마지막에 한번에
```

2. Sort Merge 조인
  - 소트 단계 : 조인 컬럼 기준 정렬
  - 머지 단계 : 정렬 된 양쪽 집합 -> 서로 merge 한다
  - /*+ ordered use_merge(e) */ 또는 option(force order, merge join)

  - 소스 머지 조인의 특징
    - 조인 전에 양쪽 집합을 정렬 -> 조인 시작
    - 부분 범위 처리 가능 -> 부분적으로 가능
    - 테이블 별 검색 조건에 의해 전체 일량 좌우
    - 스캔 위주의 조인 방식(랜덤 액세스를 사용하긴 함 -> 많이 사용시 이점이 없어짐)

```
merge join
  sort(join)
    TA DEPT
  sort(join)
    TA EMP
```

3. 해시조인(Hash Join)
  - /*+ ordered use_hash(e) */
  - option(force order, hash Join)

  - 과정
    - 작은 집합 읽어(Build Input) -> 해시영역 -> 해시 테이블(해시맵 생성)
      -> 같은 값 데이터를 같은 해시버킷에 체인 연결
    - 큰 집합(Probe Input) 읽어 해시 테이블 탐색 -> 조인 수행
  
  - 특징
    - 해시 테이블 생성 비용수반
    - 랜덤 액세스 부하 없음
    - 정렬 부담 없음
    - Build Input 작을떄 유리
    - Build Input에 중복값 적을 때 유리
    - Probe Input 읽을 때, 부분 범위 처리 가능

  - Build Input 가용 메모리 초과시
    - In-Memory 조인 불가 -> Grace 해시조인 알고리즘 사용
      - 파티션 단계  
        -> 조인 대상 양쪽 집합(조인외 조건절 포함) 조인 칼럼 기준, 동적 파티셔닝  
        -> 서브집합 분할 -> 파티션 상태의 양족 집합 모드 읽어 디스크 상 Temp 공간에 일단 저장  
        -> In-Memory 보다 성능은 떨어짐
  
    - 조인 단계
      -> 파티션 짝에 대해 하나씩 조인 수행
      -> BI, PI 가 독립적 결정(작은것은 BI, 큰것은 PI)
      
    - 분할 정복 방식 (Divide-Conquer)
    - 조인 수행시  
      -> 메모리 초과  
      -> Recursive 해시 조인  
      -> 추가 파티셔닝 진행
  
    - Build Input 해시키 중복 많을 때
      - Build Input 에 중복이 많을 수록 비효율이 발생

  - 해시 조인 사용 기준
    - 조인 컬럼에 적당한 인덱스가 없는 경우 / NL 조인 비효율
    - 조인 컬럼에 인덱스 O -> Inner 집합 액세스가 많을떄, 랜덤액세스 부하가 높을떄
    - 소트머지 조인 하기에 두 테이블이 너무 커, 소트 부하가 심할때
    - 수행빈두가 납은 쿼리며, 수행시간이 높아 대용량 테이블 조인일때
    - 단점 : 해시 테이블 -> 조인 종료시 소멸 -> cpu 와 메모리 사용율이 높고, 동시성이 낮음
