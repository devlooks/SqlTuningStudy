1. 인덱스 튜닝 기초
  - 범위 스캔이 불가능 하거나 인덱스 사용하지 않을 경우
    - 인덱스 선두 컬럼 편집
    - 부정형 비교
    - 인덱스 칼럼에 not null 제약, is null 이 아닌 조건식 하나라도 있거나, is null 조건에 대한 index scan 기능
    - 인덱스 칼럼 가공
      - 묵시적 형변환
      - 문자형/숫자형 -> 숫자형
      - 문자형/날짜형 -> 날짜형
      - 인덱스 컬럼 타입에 맞춰 조건 구성 해야됨.

2. 테이블 엑세스 최소화
   - 인덱스 ROWID에 의한 테이블 액세스
     - ROWID 구성 : 오브젝트 번호, 데이터 파일번호, 블록 번호 등.. 으로 구성(단, 직접적으로 연결X)
     - 인덱스에서 하나의 rowid의 DBA를 해시함수에 적용 해시값 확인
     - 해시값 이용 해시버킷 찾아간다
     - 해시 버킷에 연결된 해시 체인 스캔 -> 블록 헤더 찾음
     - 블록 헤더의 저장된 포인터 -> 버퍼 블록
     - 블록 헤더 찾지X -> LRU 리스트 스캔 -> Free 버퍼 찹음( 디스크 데이터 블록 적재 목적)
     - Free 버퍼 X, Dirty 버퍼 기록 -> Free 버퍼 확보
     - Free 버퍼에 적재

     - Table Access By Index RowID 또는 ROWID 기반 오퍼레이션
    
     - 클러스터링 팩터
       - 같은 값 끼리 데이터가 모여있는 정도
       - 인덱스 검색 효율이 높음
       - 물리적 근접 -> 데이터 찾는 속도가 높다
      
     - 인덱스 손익 분기점
        - Range Scan < Table Full Scan이 효율이 높아지는 지점
        - 손익 분기점 10% -> 1000개중 100개 이상 읽게 될때
          -> Table Full Scan 에 유리
        - 인덱스 손익 분기점 -> 일반적 5~20% 낮은 수준 결정
        - 클러스터링 팩터 나쁘면, 손익분기점 5% 미만, 심하면 1% 미만
      
     - 손익 분기점 극복히기
       - 클러스터형 인덱스 + IOT
       - SQL Server -> Include Index
       - 파티셔닝
       - 부분 범위 처리
      
     - 테이블 액세스 최소화 튜닝
       - 인덱스 컬럼 추가(새로 만드는 것보다 효가과가 좋음)
       - covered Index : 버려지는 레코드가 거의 없는 경우
       - Include Index :
         - create Index emp_01 on emp(deptno) include(sal)
         - Include 옵션의 컬럼을 리프블록에 저장한다 -> 수평탐색에 사용
       - 수동으로 클러스터링 팩터 높이기 -> 인덱스 기준으로 테이블 재생성
       - 배치 I/O
         - Disk I/O 를 미뤘다가 일괄 처리 -> 데이터 정렬순서가 매번 다름
         - 실행 계획의 BATCHED + ORDER BY 반드시 사용
         - order by 무조건 이용 정렬 필용

3. 인덱스 스캔 효율화
   - 랜덤 액세스를 줄이기 위한 목적
   - 시퀀셜 액세스에 의하 선택 비중을 높인다.
    1. 인덱스 선행 컬럼이 범위 조건일떄의 비효율
       - 첫 스캐시 버리는 레코드 발생(불필요한 레코드 스캔)
       - 다음 인덱스 컬럼 조건 -> 필터조건으로(Index Scan X)
    2. 범위 조건 -> IN-list 로 전환 (union all 사용 나열)
       - In-list 개수 적어야한다
       - 브런치 블록 반복 액세스 비효율 발생(반복 수직 탐색)
       - Skip Scan 사용이 유리 할 수 있음

   - 범위 조건을 2개 이상 사용 할 떄의 비효율
     - 범위조건 2개 이상 사용 -> 회사(등치) + 지역(범위) + 상품명(범위)
```
select ~ from ~
where :reg is null
and 상품명 like :prod || '%'
union all
select ~ from ~
where :reg is not null
and 회사 = :com
and 지역 = :reg
and 상품명 like :prd || '%'
```
