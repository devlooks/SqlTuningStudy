SQL Server Lock

  - lock 종류
    - 공유lock
      - 다음 레코드를 읽으면 곧바로 해제
      단, 트랜잭션 격리성 수준(Read Commited)에서만
      - 격리성 수준 변경 없이 트랜잭션에 공유 Lock유지 -> holdlock 사용
        ```
        select ~ from t with(holdlock)
        ```

  - 배타적 lock :
  - 갱신 lock : 배타 락으로 인한 교착상태 방지 -> 한 트랜잭션만 가능
    ```
    select ~ from t with(updlock)
    ```
  - 의도 lock : 로우 lock 설정 -> 내부적 의도(페이지, 익스텐트, 테이블) lock 설정 -> 일종의 푯말

  - 스키마 lock -> 스키마 의존적 작업시 사용

  - Bulk Update lock : 테이블 lock의 일종 -> Bulk Copy 시 발생

  - lock 레벨과 Escalation
    - 로우레벨 -> 로우에서만 lock
    - 페이지레벨 -> 페이지에 lock 진행 중인 로우 작업과 무관
    - 익스텐트레벨 -> 익스텐트 전체 잠김
    - 테이블레벨 -> 테이블 전체와 관련 인덱스 까지 모두 잠김
    - DB 레벨 -> DB잠김 -> 스키마 변경시 LOCK
  
  - lock Escalation 
    - lock 임계치 넘으면 -> 로우 -> 페이지 -> 익스텐트 -> 테이블 까지 락이 확장 됨
    - lock 레벨 낮을 수록 동시성이 올라김
    - lock 레벨이 높을 수록 동시성이 떨어짐

Oracle Lock

  - 로우 lock -> 항상 배타적
  - 읽기와 갱신 작업은 서로 방해하지 않음
  - lock Escalation 발생 안함
  - 읽기 시, Undo 로그 사용함

  - 테이블 lock
    - 로우 lock -> 테이블 lock으로 발생 ->  DDL 막을 목적
    - lock 종류
      - Row Share (RS)
      - ROw Exclusive (RX)
      - Share(S)
      - Share Row Exclusive (SRX)
     
      ```
      select ~ for update -> RS 모드 테이블 lock 획득
      insert, update, delete -> RX 모드 테이블 lock
      ```
      - DML -> 묵시적 테이블 lock
      - 명시적 lock 방법
        - lock table emp in row share mode;
        - lock table emp in row exclusive mode;
        - lock table emp in share mode;
        - lock table emp in share row exclusive mode;
        - lock table emp in exclusive mode;
       
  트랜잭션
    - 업무처리를 위한 논리적 작업단위
    - 특징 
      - ACID
        - 원자성 -> 전부 처리 또는 전부 실패
        - 일관성 -> 트랜잭션 성공 -> DB -> 일관된 상태
        - 격리성 -> 중간 결과를 다른 트랜잭션이 접근 못함
        - 영속성 -> 트랜잭션 성공적으로 완료 -> DB에 영속적 저장

  트랜잭션 격리성
    - Read Uncommited -> Dirty, Non-Repeatable, Phantom
    - Read Commited -> Non-Repeatable, Phantom
    - Repeatable Read -> Phantom
    - Serializable -> X

    - Dirty -> 커밋 되지 X 데이터 읽음
    - Non-Repeatable -> 같은 쿼리 두번 -> 두 쿼리 결과 다르게
    - Phatom Read -> 같은 쿼리 두번 -> 유령 레코드 추가 생성

    - Read Uncommited -> 커밋 안된 데이터 다른 TX가 읽음
    - Read Commited -> 커밋 된 데이터 다른 TX가 읽도록 허용
    - Repeatable Read -> 쿼리 두번 수행시, 레코드 사라지거나 값 변경 방지 
    - Serializable -> 쿼리 두번수행시 레코드 사라지거나 값변경이 안됨

  격리성 변경
    - set transaction isolation level read serializable

동시성 제어
  - 비관적 동시성 제어
    - 사용자가 동시에 데이터 수정, 가정
    ```
    select ~ from ~ for update
                    for update nowait
                    for update wait 3
    ```
  - 낙관적 동시성 제어
    - 사용자가 동시에 데이터 수정 X 가정
      - 수정 시점에 다른 사용자에 의해 값이 변경 했는지 반드시 검사
     ```
     select 문 ~
     update 문 ~

     if sql%rowcount = 0 then
         alert('~~')
     end if

     select ~ , 변경일자
     into ~~, :mod_dt
     from t
     where ~

     updat t
     set ~
         , 변경일시 = sysdate
     where ~
     and 변경일시 = :mod_dt
     ```

다중버젼 동시성 제어
  - MVCC 메커니즘
    - 데이터 변경시 변경사항 Undo 영역에 저장
    - 데이터 읽을때 쿼리 시작 시점 이후, 변경된 값 발견
      Undo 영역에 저장된 정보를 이용, 일관선 있는 버젼 생성(CR Copy)
    - Undo 블록 -> 오버헤드 무시
      - 오라클 Undo 데이터 -> Undo 세그먼트 저장
      - SQL Server -> tempdb에 저장
     
    - 문장 수준의 읽기 일관성(Oracle)
      - 쿠리 시작 시점 기준의 데이터 일관성
      - SQL Server 에서 문장 수준의 일기 일관성 사용
      ```
      alter database <DB 이름> set read_commited_snapshot on;
      ```
    - 트랜잭션 수준의 일관성
      - 트랜잭션 내 데이터 일관성
      - 트랜잭션 격리성 수준 -> Serializable Read로 지정
      - alter database <DB 이름> set allow_snapshot_isolation on;
     
      - 트랜잭션 시작 전
```
        set transaction isolation level snapshot
        begin transaction
        ~
        ~
        commit;
```

    - 오래 걸리는 쿼리 주간 실행 줄임
    - 큰테이블 -> 범위로 나눠 단계적 수행
    - 블록 여러번 방문 회피(NL, 인덱스 스캔)
   
    - 소트 연상 필수 사용
    - 대량 업데이트시, 바로 인덱스 full Scan 수행
