  - 항목 Call
    - Parse : 커서 파싱, 실행 계획 생성
    - Execute : 커서 실행 단계에 대한 통계
    - Fetch : 레코드 실제로 Fetch 통계
    - count : 각 단계 수행횟수
    - cpu : 커서 단계 사용한 cpu time
    - elapsed : 커서 수행 시간
    - disk : 디스크로 부터 읽은 블록수
    - query : consistent 모드에서 읽은 블록수
    - current : current 모드에서 일긍 블록 수
    - rows : 처리 건수
   
  - Auto Trace 항목과 비교
    - db block gets = current
    - consistent gets = query
    - physical reads = disk
    - SQL*Net round trip to/from client = fetch count
    - row processed = fetch rows
   
  - DBMS_XPLAN 패키지
    - Starts : 실행 횟수
    - E-Rows : 예상 건수
    - A-Rows = rows - 읽거나 갱신건수
    - A-Time = time - 각 단계별 소요 시간
    - Buffers = cr - 캐시 버퍼 읽는 버퍼 블록
    - Reads = pr - 디스크에서 읽은 블록
   
    - 예시 : select * from table(dbms_xplan.display_cursor(null, null, 'ALLSTATS LAST') - 마지막 수행 일량
   
  - SQL Server
    - set statistics profile on : 쿼리 실행 프로필
    - set statistics io on : 디스크 동작 양에 대한 정보
    - set statistics time on : 사용한 시간 밀리 초 단위 표시
   
4. 응담 시간 분석
   - 라이브러리 캐시 부하
     - 라이브러리 캐시에서 SQL 커서 찾과 최적화 과정중 경합 발생의 의미
     - latch : shared pool, library cache
     - DDL 수행시 대기 이벤트
       - library cache lock
       - libreary cache pin
     - 라이브러리 캐시 관련 경합 급증 -> 심각한 동시성 저하
    
   - DB Call과 네트워크 부하
     - SQL*Net message from Client :
       - 다음 명령어 올떄까지 Idle 상태로 대기
     - SQL*Net message to client / SQL*Net more data to client
       - 메세지를 받았다는 신호, 정해진 시간보다 늦게 도착
     - SQL*Net more data from client
       - 더 받을 데이터가 있는데 지연 발생
     - 버퍼캐시 경합
       - latch : cache buffers chains
       - latch : cache buffers lru chain
       - buffer busy waits
       - free buffer waits
      
     - lock 관련 대기 이벤트
       - enq : TM - contention
       - enq : TX - row lock contention
       - enq : TX - index contention
       - enq : TX - allocate ITL entry
       - enq : TX - contention
       - latch free : 특정 자원 2000번 가량 요청 -> 계속 사용중 -> 대기상태 발생 (queue사용 하지 않음)
     - 그외 대기 이벤트
       - log file sync
       - checkpoint completed
       - log file switch completion
       - log buffer space

      - AWR 기본 사용법
        - sys 계정 하위 dba_hist 시작하는 뷰 이용
        - peak 시간대 분석 -> sar, topas, umstat, osstat 등 사용 파악
        - 장애 발생 시점 전후 가능한 짧은 구간

      - AWR 리포트 분석
        - 첫장
          - 부하 프로필
          - 인스턴스 효율성
          - 공유풀
          - 통계
          - 최상위 5개 대기 이벤트 등 구성
         
      - 부하 프로필
        - per second : 초당 부하 발생량

      - 인스턴스 효율성
        - Execute to Parse % 제외 모드 100% 가까운 수치 -> 정상
       
      - 공유 풀 통계
        - AWR 리포트 구간 시작 시점의 공유 풀 메모리 상황과 종료시점 메모리 상황
       
      - 최상위 5개 대기 이벤트
        - cpu time 비중이 높다 -> db건강 상태 양호
        - cpu time 이 아래로 밀려날 수록 이상 현상 발생
        - 상위에 있다해서 이상 징후로 해석 하면 안됨
        - db sequential, db fhile scattered read -> 상위 -> 정상
        - cpu 사용률이 높은 상태 지속 -> I/O 튜닝 필요 시스템템
