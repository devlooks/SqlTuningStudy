# 🛡️ 1. Static Pruning vs Dynamic Pruning 비교

| 구분 | Static Partition Pruning | Dynamic Partition Pruning |
|---|---|---|
| **결정 시점** | SQL 컴파일/하드파싱 시점 | SQL 런타임(실행) 시점 |
| **조건 형태** | 상수 리터럴 (`ORD_DT = '20260801'`) | 바인드 변수, 서브쿼리, 조인 연결고리 |
| **실행계획 Pstart / Pstop** | `1` ~ `1` (또는 특정 파티션 번호) | `KEY` ~ `KEY` (또는 `KEY(INLIST)`) |
| **핵심 주의점** | 파티션 키 컬럼 가공(`SUBSTR`, 형변환) 금지 | **선행 테이블로부터 값을 건네받는 `Nested Loops 조인(USE_NL)`**에서만 작동 |

# ⚡ 2. 파티션 키 없는 Top-N 조회 시 로컬 vs 글로벌 인덱스

### 💡 왜 파티션 키 없는 조건의 Top-N에 로컬 인덱스는 치명적인가?
* 로컬 인덱스는 **각 파티션 내부에서만 정렬**되어 있습니다.
* 따라서 `WHERE ROWNUM <= 10 ORDER BY REG_DT DESC`를 실행할 때, 오라클은 12개 또는 365개 **모든 파티션의 로컬 인덱스를 전부 뒤져서 데이터를 모은 뒤 최종 `SORT ORDER BY STOPKEY`**를 수행해야 하므로 파티션 개수만큼 I/O가 폭발합니다.

### 🏆 [물리적 해결책] 글로벌 비파티션 인덱스 (Global Non-Partitioned Index)
* **인덱스 생성:** `CREATE INDEX IX_TB_ORD_GLOBAL ON TB_ORD(ORD_STAT, REG_DT DESC);`
* **동작 원리:** 테이블이 수백 개 파티션으로 쪼개져 있어도, 인덱스는 전체 테이블에 대해 단일 B-Tree로 완벽히 정렬되어 있으므로 **단 10건만 읽고 즉시 `COUNT STOPKEY`로 종료 (정렬 연산 100% 제거)!**
