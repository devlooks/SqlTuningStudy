# SQLP 실기 2회독 학습계획 v2

- **기준일:** 2026-08-11
- **마스터 범위 문서:** `SQLP_실기_2회독_통합패턴맵_v2_3_최종확정`
- **문제 생성/검수 문서:** `SQLP_실기_2회독_문제출제규칙_v2`
- **출제경향 참고 문서:** `SQLP_실기_검증된_출제경향_및_시험전략_v1_1`
- **목적:** 통합패턴맵의 S/A 패턴을 일정 내 반복 순환하면서, 테마 비공개 상태에서도 `식별 → 진단 → 개선 → 결과집합 검증 → TO-BE 예상`을 독립 수행할 수 있도록 한다.

# 1. 문서 역할과 우선순위

## 1.1 역할 분리

본 문서는 **무엇을 공부할지 정의하는 문서가 아니라, 언제·어떤 순서·어떤 종료기준으로 공부할지를 정의하는 운영 문서**다.

- 학습 범위와 중요도: **통합패턴맵 최신 버전**을 따른다.
- 문제 생성 및 검수: **문제출제규칙 최신 버전**을 따른다.
- 시험 직접성 및 출제경향: **검증된 출제경향 및 시험전략 최신 버전**을 참고한다.
- 본 문서와 통합패턴맵이 충돌하면 **통합패턴맵을 우선**한다.

## 1.2 Pattern ID 기준 운영

학습·오답·복습·숙련도는 테마 이름만으로 관리하지 않고 **Pattern ID**를 기준으로 기록한다.

예:

- 원자 패턴: `C01`, `J07`, `Q01`, `PT05`, `PX08`
- 복합 패턴: `CP01`, `CP03`, `CP17`, `CP33`

새로운 SQLP 근거 또는 Oracle 튜닝 소스가 추가되어 범위가 변경되면 **통합패턴맵을 먼저 갱신한 뒤 본 학습계획을 재검토**한다.

# 2. 1회독 평가와 2회독 전제

## 2.1 1회독 평가

1회독에서는 주요 SQL 튜닝 패턴을 폭넓게 학습하고 실제 문제를 반복 풀이하였다.

다만 2회독에서는 단순히 동일한 패턴을 다시 설명하는 방식이 아니라 다음 부족점을 보완한다.

1. 개별 개념 이해와 **복합 상황에서의 독립 판단** 사이의 차이
2. 실행계획의 `Starts / A-Rows / 단계별 Cardinality`를 실제 데이터 흐름으로 연결하는 능력
3. 일반 Join / Semi / Anti / Outer 관계를 SQL 출력 요구와 데이터 모델에서 먼저 판정하는 능력
4. 개선 SQL의 성능만이 아니라 **결과집합 동일성**까지 검증하는 습관
5. 특정 한 패턴을 지나치게 오래 파면서 전체 진도가 지연되는 문제
6. 이미 학습한 내용을 다시 처음부터 설명하기보다 실제 오답 Pattern ID를 중심으로 복습하는 체계

## 2.2 실제 풀이 기록 사용

숙련도는 추정하지 않는다.

현재 프로젝트의 실제 제출 답안, 오답, 재질문, 독립 재현 성공 여부를 근거로만 판정한다.

근거가 충분하지 않은 Pattern ID는 **미평가**로 유지한다.

# 3. 2회독 최종 목표

2회독 종료 시 핵심 S/A 패턴에 대해 다음을 독립 수행할 수 있어야 한다.

1. 테마가 공개되지 않은 SQL과 Execution Plan에서 병목 후보를 식별한다.
2. Row Source의 입력·출력 건수와 `Starts / A-Rows` 흐름을 설명한다.
3. 데이터 모델과 출력 요구로 일반 / Semi / Anti / Outer 관계를 판정한다.
4. Access Path, Join Method, Join Order, Query Transformation, Partition, PX, DML 등의 개선 방향을 선택한다.
5. 필요한 경우 SQL / Hint / Index / DDL을 재작성한다.
6. 개선 SQL과 원본 SQL의 결과집합 동일성을 설명한다.
7. 예상 TO-BE Execution Plan의 핵심 Row Source와 데이터 흐름을 설명한다.
8. 불필요한 힌트나 Row Source를 구분한다.
9. 정답을 본 뒤 이해하는 수준이 아니라 **테마 비공개 상태에서 독립 재현**한다.

# 4. 학습 우선순위

통합패턴맵 v2.3의 중요도 등급을 그대로 사용한다.

## 4.1 S 패턴

- 2회독의 중심이다.
- 반드시 **날짜/세션을 배정**한다.
- 해당 날짜 안에서 기본 → 중급 → 고급 수준을 진행한다.
- 이해가 부족하더라도 한 테마를 무제한 연장하지 않는다.
- 미해결 항목은 오답 큐로 보내고 예정된 다음 테마로 이동한다.

## 4.2 A 패턴

- 독립 테마로 장기간 배정하지 않는 것을 기본으로 한다.
- 관련 S 패턴에 결합하여 문제화한다.
- 실제 오답이 반복되는 A 패턴만 별도 보강 세션을 허용한다.

## 4.3 B 패턴

- S/A 복합문제의 보조축으로 사용한다.
- B 패턴 때문에 S/A 진도를 지연시키지 않는다.

## 4.4 C 및 F 패턴

- 개념 확인 및 공식범위 안전망 용도다.
- 2회독 실기 핵심 진도와 분리한다.
- 실전형 문제 비중을 과도하게 부여하지 않는다.

# 5. 테마 구성 원칙

## 5.1 테마는 Taxonomy 단위가 아니라 판단 흐름 단위로 묶는다

통합패턴맵의 21개 상위 Taxonomy를 그대로 하루씩 공부하지 않는다.

실제 문제 해결 과정에서 함께 판단되는 S 패턴들을 하나의 **학습 테마군**으로 묶는다.

### 핵심 테마군

| 테마군 | 주요 Pattern 축 | 대표 판단 |
|---|---|---|
| T01 Cardinality / 실행계획 기본 | C01~C10, E01~E03, E09~E12, M01~M05 | 입력→출력 건수, Starts, 관계 다중성 |
| T02 Predicate / Access / Index | P01~P10, A01~A12, I01~I08 | Sargability, Access/Filter, 인덱스 선택 |
| T03 Join Method / Join Order | J01~J12 | NL/Hash/Merge, Driving, Build/Probe |
| T04 Semi / Anti / DISTINCT | J07/J08/J10, Q01/Q02, R02/R03/R07, CP01~CP03 | 존재성/부재성, 중복 증폭 제거 |
| T05 Scalar Subquery / Query Transformation | Q01~Q08, Q13~Q15, R04/R12/R13/R15 | 반복 Starts, Unnest, Push, Merge |
| T06 Optional Predicate / OR Expansion | P04/P05/P07, Q07, R05/R17, CP05/CP25/CP43 | 호출유형별 선택도와 분기 |
| T07 GROUP BY / Sort / Top-N | C08~C10, O01~O06, G01~G10 | 집계 위치, 정렬, Stopkey, Analytic |
| T08 Partition / Pruning | PT01~PT10, P01/P03 | Static/Dynamic Pruning, Partition DDL |
| T09 Partition-Wise Join / Parallel | PT05/PT06, PX01~PX12 | Full/Partial PWJ, PX 분배, DOP |
| T10 DML / Batch / DDL | D01~D09, PT08~PT10 | DELETE/INSERT/UPDATE, CTAS, EXCHANGE |
| T11 Runtime / Trace / DB Call | SC01~SC10, T01~T07, TR01~TR10 | Parse/Execute/Fetch, I/O, Response Time |
| T12 Lock / Transaction / Concurrency | L01~L07, D07~D09 | Lock, Long Transaction, Commit, DML 부담 |
| T13 종합 복합 튜닝 | CP01~CP45 중 S/A | 테마 비공개 AS-IS → TO-BE 종합 판단 |

> 위 테마군은 학습 운영용 묶음이며 **패턴의 실제 중요도와 범위 정의는 통합패턴맵이 기준**이다.

# 6. 날짜/세션 배정 원칙

## 6.1 기본 원칙

- 학습 가능일이 정해지면 **각 S 중심 테마군에 먼저 날짜를 배정**한다.
- 일정은 한 테마의 완벽한 숙달을 기다렸다가 다음 테마로 넘어가는 직렬 방식으로 운영하지 않는다.
- 예정된 날짜가 끝나면 숙련도가 부족해도 다음 테마로 이동하고, 부족한 Pattern ID를 오답 큐에 기록한다.
- 오답은 별도 복습 세션 또는 다음 순환에서 재등장시킨다.

## 6.2 1회 학습시간 기본값

기존 계획의 기본값을 유지하여 **1회 1.5~2시간**을 기준으로 한다.

학습 가능 횟수는 실제 일정에 따라 조정하되, 각 세션의 내용은 다음 구조를 따른다.

### 일반 테마 세션

1. 이전 오답/Execution Plan 단편 복습: 10~20분
2. 기본/중급 문제: 30~40분
3. 고급 또는 복합 문제: 40~50분
4. 오답 Pattern ID 기록 및 핵심 원리 정리: 10~20분

### 실전 세션

1. 테마 비공개 문제 풀이
2. 시간 제한 적용
3. AS-IS → Rewrite → TO-BE까지 연속 작성
4. 채점 후 오답 Pattern ID만 복습 큐로 이동

## 6.3 한 테마의 시간 상한

한 테마가 예정된 학습일을 초과해 전체 진도를 막지 않도록 한다.

- 기본적으로 **한 테마군은 배정된 세션 안에서 종료**한다.
- 추가 연습이 필요하면 즉시 같은 테마를 계속 연장하지 않고 **오답 큐**로 이동한다.
- 같은 Pattern ID가 반복 오답이면 다음 순환에서 보강 세션을 배정한다.

# 7. 한 테마의 문제 진행 단계

한 테마를 다음 순서로 진행한다.

## 7.1 기본

- 핵심 S 패턴 1개 중심
- 병목 위치가 비교적 명확함
- Cardinality 계산이 독립적임
- 필요 시 테마 단서를 일부 제공 가능

## 7.2 중급

- S + A 2~3개 결합
- 판단들이 서로 연결됨
- SQL Rewrite 후 결과집합 검증 포함

## 7.3 고급

- S/A 다수 결합
- 한 판단이 다른 Row Source의 Starts/A-Rows에 연쇄 영향
- 불필요 연산과 필수 연산이 혼재
- AS-IS만 보고 개선 방향을 도출

## 7.4 실전

- 테마 비공개
- 불필요 Hint/Row Source 함정 가능
- 시간 제한
- 결과집합 동일성 검증 필수
- 단순 정답 선택이 아니라 `AS-IS 진단 → SQL/Hint/Index/DDL → TO-BE`를 연속 수행

# 8. 문제 풀이 기본 형식

모든 일반 2회독 문제는 다음 기본 출력 순서를 따른다.

## 1. AS-IS 병목 판단

- Row Source 식별
- 단계별 건수 흐름
- Starts / A-Rows
- Access / Filter Predicate
- 일반 / Semi / Anti / Outer 관계
- 병목의 직접 원인

## 2. SQL + Hint / Index / DDL 재작성

- 결과집합을 보존하는 개선안 작성
- 필요한 Hint만 사용
- 불필요한 Hint 강제를 피함

## 3. TO-BE 실행계획 예상

- 핵심 Row Source
- Access Path
- Join Method / Join Order
- 제거되는 연산
- 예상 Starts / A-Rows 변화
- Partition / PX 문제라면 데이터 이동 흐름까지 설명

문제 특성상 SQL Rewrite가 필요하지 않거나 DDL/Trace형인 경우에는 2단계를 해당 문제의 개선 행위로 대체한다.

# 9. 한 테마 종료 조건

한 테마의 **학습 세션 종료**와 **숙달 판정**을 분리한다.

## 9.1 세션 종료 조건

배정된 학습시간이 끝나고 다음 항목을 최소 한 번 수행했으면 해당 테마 세션을 종료한다.

1. 병목 Row Source 식별
2. 건수 흐름 / Starts 계산
3. 논리적 관계 판정
4. SQL / Hint / Index / DDL 개선안 제시
5. 결과집합 동일성 설명
6. 예상 TO-BE Plan 핵심 Row Source 설명

틀린 항목이 있더라도 진도를 멈추지 않고 오답 큐에 기록한다.

## 9.2 숙달 조건

아래를 테마 비공개 문제에서 독립적으로 수행할 때 숙달로 판정한다.

- 패턴 식별
- 직접 원인 설명
- 개선안 선택
- 결과집합 검증
- TO-BE 핵심 흐름 설명

즉 **세션 종료 = 숙달**이 아니다.

# 10. 숙련도 판정

통합패턴맵의 정의를 그대로 따른다.

| 상태 | 기준 |
|---|---|
| 미평가 | 실제 풀이 근거가 충분하지 않음 |
| 미학습 | 원리 설명 자체가 어려움 |
| 미숙달 | 단독 패턴에서도 반복 오류 |
| 부분숙달 | 단독은 가능하지만 복합에서 오류 |
| 숙달 | 테마 비공개 상태에서 식별→개선→검증 독립 수행 |

숙련도는 단순히 정답 1회를 맞혔다는 이유만으로 올리지 않는다.

# 11. 오답 관리

## 11.1 오답 기록 단위

오답 발생 시 다음을 기록한다.

- 날짜
- 문제 ID
- 원자 Pattern ID
- 관련 Composite Pattern ID
- 오류 단계
  - 관계 판단
  - Cardinality
  - Starts/A-Rows
  - 병목 선정
  - Rewrite
  - Hint
  - 결과집합
  - TO-BE Plan
- 오류 원인 한 줄
- 재검증 결과

## 11.2 재출제 원칙

오답은 같은 문제를 바로 반복하기보다 다음 순서로 재출제한다.

1. 동일 Pattern의 다른 수치/데이터 모델
2. 동일 Pattern + 다른 A 패턴 결합
3. Composite Pattern 문제
4. 테마 비공개 실전문제

## 11.3 반복 오답

같은 Pattern ID에서 반복 오류가 발생하면 다음 순환에서 해당 Pattern을 **보강 대상**으로 지정한다.

단, 당일 학습을 무제한 연장하지 않는다.

---

# 12. Execution Plan 단편 훈련

Execution Plan 판독은 별도의 긴 테마로 분리하지 않고 모든 세션에 짧게 반복한다.

주요 훈련 대상:

- `Starts / A-Rows / E-Rows`
- NL Inner Starts
- Scalar / FILTER Subquery Starts
- HASH JOIN 입력/출력
- GROUP BY 입력/출력
- UNIQUE 전후 건수
- Access vs Filter Predicate
- `Pstart / Pstop`
- PX SEND / RECEIVE 데이터 흐름
- DOP와 Starts
- 필수 Row Source vs 제거 가능 Row Source

목표는 실행계획을 암기하는 것이 아니라 **Row Source 데이터 흐름을 수치로 읽는 것**이다.

---

# 13. 순환 학습 구조

2회독은 한 번의 직선 진도가 아니라 다음 순환 구조로 진행한다.

## Cycle A — S 패턴 전체 재노출

- T01~T12 핵심 테마를 일정에 따라 빠르게 순환
- 기본 → 중급 → 고급
- 한 테마 무한 반복 금지
- 오답 Pattern ID 수집

## Cycle B — 취약 Pattern + 복합 패턴

- Cycle A에서 수집된 미숙달/부분숙달 Pattern 우선
- A 패턴 결합 비중 증가
- Composite Pattern 문제 증가
- 테마 공개 최소화

## Cycle C — 실전 통합

- T13 종합 복합 튜닝 중심
- 테마 비공개
- 시간 제한
- AS-IS → Rewrite → TO-BE 전체 수행
- 실제 시험형 답안 압축 연습

2회독의 목적은 모든 Pattern을 같은 횟수만큼 푸는 것이 아니라, **S 패턴 전체를 빠짐없이 재노출한 뒤 오답 근거에 따라 반복량을 차등 배분**하는 것이다.

---

# 14. B/C/F 영역 운영

B/C/F 영역은 S/A 실기 진도와 분리한다.

- B: 관련 S/A 문제에서 보조 개념으로 출제
- C: 개념 확인 위주
- F: SQLP 공식범위 안전망으로 별도 기초 복습

다음과 같은 저우선 영역은 S/A 일정이 밀릴 정도로 깊게 학습하지 않는다.

- AWR / ASH / ADDM / SQL Monitor 세부 운용
- SQL Plan Baseline / Profile / Patch
- Star Transformation / MV Rewrite / Table Expansion 등 직접 출제 근거가 약한 고급 변환
- 개별 Wait Event 세부 암기
- 모든 Optimizer Parameter 세부 암기

새로운 공식/검증 근거가 확보되면 통합패턴맵의 중요도를 먼저 갱신한 후 학습 비중을 변경한다.

---

# 15. TO-BE 제공 전략

TO-BE 제공 여부는 단순히 숙련도가 높을수록 더 많이 제공하는 방식으로 고정하지 않는다.

문제 목적에 따라 다음 유형을 혼합한다.

- **A형 — AS-IS Only:** 스스로 병목과 TO-BE를 도출
- **B형 — 목표 Plan 제공:** 제공된 TO-BE를 역설계해 SQL/Hint 작성
- **C형 — 부분 TO-BE 제공:** 일부 Plan/Hint만 주고 나머지 추론
- **D형 — 완전 실전형:** 테마·개선방향·TO-BE 모두 비공개

2회독 초반에는 AS-IS 진단 능력을 우선 확인하고, 후반으로 갈수록 여러 유형을 섞어 특정 문제형식에 의존하지 않도록 한다.

---

# 16. 복습 빈도 결정

복습량은 Pattern 중요도와 실제 오답을 함께 사용한다.

### 우선순위 1
- S + 미숙달
- S + 반복 오답

### 우선순위 2
- S + 부분숙달
- A + 반복 오답

### 우선순위 3

- A + S 복합문제

### 우선순위 4
- B/C/F 보조 확인

이미 숙달된 단독 S 패턴을 계속 반복하기보다 **복합문제 안에서 재검증**한다.

# 17. 2회독 종료 조건

다음 조건을 모두 만족할 때 2회독 종료를 검토한다.

1. 통합패턴맵의 **S Pattern 전체가 최소 한 번 이상 2회독 일정에 포함**됨
2. 핵심 S Pattern에서 미학습 상태가 없음
3. 반복 오답 S Pattern에 대해 재출제 검증 완료
4. 주요 S Pattern을 테마 비공개 문제에서 독립 식별 가능
5. `Starts / A-Rows / Cardinality` 계산을 문제 해결 과정에서 안정적으로 수행
6. 일반 / Semi / Anti / Outer 관계를 결과집합 기준으로 판정 가능
7. SQL / Hint / Index / DDL 개선 후 결과집합 동일성 설명 가능
8. 예상 TO-BE Plan의 핵심 Row Source를 독립적으로 설명 가능
9. 종합 복합문제에서 특정 한 패턴만 보는 것이 아니라 복수 병목의 우선순위를 결정 가능
10. 제한된 시간 안에 시험형 답안을 작성할 수 있음

모든 S Pattern을 반드시 `숙달`로 표시해야만 2회독이 끝나는 것은 아니다. 남은 부분숙달 항목은 3회독의 우선 복습 대상으로 승계할 수 있다.

# 18. 3회독 진입 기준

2회독 종료 조건을 충족한 뒤 3회독은 다음 방향으로 전환한다.

- 단독 테마 문제 최소화
- Composite Pattern 중심
- 테마 완전 비공개
- 시간 제한 강화
- 실제 시험형 문제 단위로 통합
- 오답 패턴만 선택적으로 기본 문제로 회귀

즉 3회독의 중심은 **새로운 패턴 학습이 아니라 실전 재현성과 속도**다.

# 20. 일정 변경 원칙

다른 공부나 일정으로 SQLP 학습량이 줄어드는 경우에도 다음 순서를 유지한다.

1. S 테마 날짜를 우선 보존
2. A 독립학습 축소
3. B/C/F 학습 축소 또는 다음 순환으로 이월
4. 문제 수를 줄이더라도 `AS-IS → Rewrite → TO-BE` 구조는 유지
5. 이미 배정된 한 테마를 장기간 연장하기보다 전체 S Pattern 재노출을 우선

학습 가능일 또는 시험일이 변경되면 **테마별 날짜 배정표만 재계산**하고, 본 문서의 학습 원칙은 유지한다.

# 21. 최종 운영 원칙

1. **범위는 통합패턴맵이 결정한다.**
2. **S 패턴은 반드시 날짜를 배정한다.**
3. **한 패턴을 완벽해질 때까지 무제한 파지 않는다.**
4. **오답은 Pattern ID로 관리하여 다음 순환에 재투입한다.**
5. **A는 S와 결합하고 B/C/F는 S/A 진도를 방해하지 않는다.**
6. **문제는 AS-IS → 개선 → TO-BE 흐름으로 푼다.**
7. **Starts/A-Rows/Cardinality와 결과집합 동일성을 모든 문제의 공통 검증축으로 둔다.**
8. **숙련도는 실제 제출 답안과 재현 결과로만 갱신한다.**
9. **새로운 범위 근거가 생기면 통합패턴맵을 먼저 수정한다.**
10. **2회독은 전체 S 패턴 재노출과 취약패턴 선별이 목적이며, 3회독에서 실전 통합도를 높인다.**

# 22. v1 → v2 주요 변경사항

1. `실제 대화 기반 자료는 없음` 전제를 제거하고 실제 프로젝트 풀이 기록을 숙련도 근거로 사용하도록 수정.
2. 잘못된 `1~19절`, `17절` 참조 제거.
3. 통합패턴맵 v2.3을 범위의 Single Source of Truth로 명시.
4. S/A/B/C/F 중요도에 따른 학습 비중을 통합패턴맵과 일치시킴.
5. **S 패턴 날짜 지정 + 한 테마 무제한 반복 금지** 원칙 추가.
6. 학습 세션 종료와 패턴 숙달을 분리.
7. 미숙달 패턴을 당일 계속 파지 않고 **오답 큐 → 다음 순환**으로 이동하도록 변경.
8. Pattern ID / Composite Pattern ID 기반 오답 관리 도입.
9. 통합패턴맵 전체를 실제 문제 해결 흐름에 맞춘 T01~T13 학습 테마군으로 재구성.
10. 실행계획 단편 훈련을 모든 세션에 반복 삽입.
11. Cycle A → B → C 순환형 2회독 구조 도입.
12. B/C/F 저우선 영역이 핵심 S/A 진도를 방해하지 않도록 명문화.
13. 2회독 종료조건을 실제 독립 수행 기준으로 구체화.
14. 시험일/학습 가능일 변경 시 전체 원칙을 바꾸지 않고 **날짜 배정표만 재계산**하도록 분리.

## 23.4 Cycle C — 실전 통합

목표: 특정 테마의 정답을 재현하는 것이 아니라 **AS-IS → 개선 → TO-BE**를 시간 내 완주한다. 모든 문제는 기본적으로 테마 비공개로 한다.

## 23.5 일정 미준수 시 재배정 규칙

1. 한 날짜를 놓쳐도 다음 모든 일정을 뒤로 미루지 않는다.
2. 누락 세션은 가장 가까운 `Cycle 점검일` 또는 다음 동일축 세션에 병합한다.
3. S Pattern 노출 자체가 누락될 경우 B/C/F 세션을 줄여 S를 복구한다.
4. 반복 오답이 있어도 같은 테마를 연속으로 무제한 배정하지 않는다.
5. 12월 초까지 2회독 종료조건을 충족하지 못하면 미숙달 S Pattern만 추가 보강하고, 이미 안정적인 테마의 반복은 줄인다.

## 23.6 2회독 이후 연결

- 12/06 점검에서 종료조건을 충족하면 이후 학습은 **3회독 실전 통합**으로 전환한다.
- 3회독은 통합패턴맵의 새로운 범위를 추가 학습하는 단계가 아니라, `Composite Pattern + 테마 비공개 + 시간 제한 + 답안 압축` 중심으로 운영한다.
- 2회독에서 남은 부분숙달/미숙달 Pattern ID를 3회독 우선순위로 승계한다.
